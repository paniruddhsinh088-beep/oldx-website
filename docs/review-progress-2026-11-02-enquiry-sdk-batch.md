# Isolated Provider enquiry SDK adapter — 2 November 2026

This review-only adapter is **disabled by default** and requires an explicit `enabled:true` plus a demo-only, loopback, non-SSL Firestore SDK context. It is not connected to HTTP, browser, staging, production, credentials, deployed Rules or any real Firebase project. No cloud resources or migrations are authorized.

`scripts/firebase-provider-enquiry-repository.mjs` maps the existing private enquiry transaction to SDK-shaped atomic record/receipt/audit writes. The adapter reads the current global generation, canonical owner/identity/publication/public view and eligibility, and requires **both** explicit participant-block records (missing/unknown blocks fail closed). Private reads are transaction-scoped, role-derived from the server-provided verified actor UID, and passed through the existing participant DTO projector. A caller must supply a trusted verified actor, not a browser-selected UID. The demo-only `PROVIDER_ENQUIRY_TEST_SCHEMA` is not a deployment schema; no persistence is active.

SDK-shaped tests cover concurrency/idempotency, cross-account denial, withdrawal, blocks, tampered source, cancellation, malformed staged payload and atomic failures. They use a deterministic in-memory SDK double, **not an actual Firebase Emulator**. Actual Emulator Rules, real Auth/revocation, rate/quota, retention, audit, indexes, operational transaction limits and explicit owner staging approval are still required. The single-process mock and test paths do not establish production durability. HOLD/NO-GO remains.

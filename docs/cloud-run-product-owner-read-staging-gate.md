## Staging routing and authentication

1. Start with a private Cloud Run service and a named staging tester with service-level `roles/run.invoker`. The Google-signed service audience token goes in `X-Serverless-Authorization`. The distinct Firebase staging user token goes in `Authorization`. The application derives identity from the verified Firebase token and checks revocation, actor eligibility and ownership. The two credentials are independent. [Cloud Run service-to-service authentication](https://docs.cloud.google.com/run/docs/authenticating/service-to-service)
2. Keep Pages static and its existing API fallback until direct private acceptance passes. For later browser acceptance, propose one staging-only Pages Function for exact `POST /api/staging/marketplace/owner`, with a fixed approved HTTPS service origin and an exact route allowlist. Strip client invoker/identity headers, enforce the 32 KiB request limit, forward only the Firebase bearer and JSON, add a server-obtained Google invoker token, reject upstream redirects and use private no-store responses. Return a generic error on failure without falling back to HTML. Apply no token or private DTO logging at either hop. No route or origin changes are needed for production or Capacitor in this slice. [Pages Functions routing](https://developers.cloudflare.com/pages/functions/routing/)
3. The Pages Function still needs an independently reviewed, tested keyless Google token source. Do not assume Pages provides a federatable identity. Any external identity provider or Workload Identity Federation trust requires separate approval. Keep Cloud Run private and leave Pages routing off until that dependency is established. [Cloud Run external authentication](https://docs.cloud.google.com/run/docs/authenticating/service-to-service)

## Final offline preflight

### Pages workload identity verdict

Google supports a keyless external call when an independently trusted provider issues a renewable, signed **workload** assertion. The flow is provider assertion → Google STS → IAM Credentials `generateIdToken` for the Cloud Run service audience → `X-Serverless-Authorization`. Restrict the provider mapping and conditions to the exact staging workload and audience, and give the federated principal only `iam.serviceAccounts.getOpenIdToken` on an invoker-only account if the approved exchange supports that grant. The Firebase user bearer remains separate. [Google external invocation](https://docs.cloud.google.com/run/docs/authenticating/service-to-service) · [Workload assertion requirements](https://docs.cloud.google.com/iam/docs/use-workload-identity-federation-to-let-customers-access-their-cloud-resources) · [Token minting permissions](https://docs.cloud.google.com/iam/docs/service-account-permissions)

No documented native Pages Function workload assertion or tested trust binding was found. A Pages Service binding reaches a Worker and does not establish a Google principal. The Access plugin validates incoming Access assertions and does not supply a Pages workload assertion. GitHub OIDC identifies a workflow job. It does not identify the deployed Pages Function at request time. Service account keys and shared service tokens do not meet this keyless gate. [Pages bindings](https://developers.cloudflare.com/pages/functions/bindings/) · [Access plugin](https://developers.cloudflare.com/pages/functions/plugins/cloudflare-access/) · [GitHub workflow federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines)

**Decision:** Keep Pages static for the first private staging test and use a named Google tester plus a separate synthetic Firebase identity. If browser-only staff acceptance is later needed, evaluate direct Cloud Run IAP as a distinct, separately approved user-access design. IAP grants invocation to its service agent and gates staff access. It does not give Pages a workload identity. Public invocation is outside this plan. [Developer authentication](https://docs.cloud.google.com/run/docs/authenticating/developers) · [Direct IAP](https://docs.cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run)
